# dsh-token-usage-panel

一个 DeepSeek Harness 插件：在**侧边栏**添加一个入口（"Token 用量"），提供**两个视图**：

- **概览**：KPI 条 + Token 活动热力图 + 每日趋势（多模型折线）+ 模型用量环图；
- **会话**：总消耗与构成、按模型拆分、可筛选可排序的会话明细表（含导出）。

**没有金额**。这个插件的职责是"用量"，不是"账单"：一张写死的价目表几周内就会过期，然后自信地画出错误的金额。代码、配置、文案、导出里都不含价格。

## 安装

零依赖：`package.json` 里没有 `dependencies`，装它不会往 profile 引入任何第三方包。

**图形界面**：侧栏「插件」页 →「添加插件」→ 填 `dsh-token-usage-panel` → 安装 → **重启 DSH** 并刷新浏览器。

**命令行**：

```sh
dsh plugin --profile <profile-name> add dsh-token-usage-panel
```

装完必须重启一次 DSH：Host 半场（三个投影单元）是**已加载模块**，平台 HMR 默认不监听插件目录；不重启就只有浏览器半场，面板会提示缺少按天数据。

老会话早于本插件写入，缺这三个单元，会在**第一次打开面板**时补读（折叠历史日志、不激活 Agent、底部显示进度）。所以刚装完概览先是空的、随后自己填满，这是正常行为而不是出错。

两个视图的滚动模型不同，各自都是明确的：

| 视图 | 滚动 |
| --- | --- |
| 概览 | `[data-view=overview]` 上的 `overflow-y:auto` **文档流**（卡片堆叠） |
| 会话 | 根 `overflow:hidden`；**`.dshTup_sessions` 自身** `flex:1 1 auto; min-height:0; overflow-y:auto`（整页滚动）；标题/概览/模型条/筛选/页脚/表格带全部 `flex:0 0 auto`，卡片取自然高度 |

会话视图这条契约有静态断言守着。它的历史是两次真实的裁剪事故：先是"唯一可收缩者"的固定 chrome + 表格组合——表格被压到下限后其余卡片溢出，根的 `overflow:hidden` 静默吞掉；后来分页（`PAGE_SIZE = 20`）让行数有界，`windowRange` 永不触发，于是表格带不再需要定高，整页滚动成为唯一滚动容器。**不要把某个成员设成唯一可收缩者，也不要给表格带定高**（`height:min(52vh,…)` 那类写法用视口量面板，矮面板反而更高，已被断言禁止）。

## 数据来源（五个投影单元）

| 投影键 | 内容 | 保留窗口 |
| --- | --- | --- |
| `tokenUsage` | 官方 `dsh-token-meter`：四个计数桶 | 全量 |
| `sessionStats` | 官方 `dsh-session-stats`：轮次 | 全量 |
| **`tokenUsageByRoute`** | 按 provider/model 的用量（含网关名与模型显示名） | 全量 |
| **`tokenUsageByDay`** | 按天用量 + 会话时间跨度 + 折叠用的 UTC 偏移 | 最近 366 天 |
| **`tokenUsageByRouteByDay`** | 按天 × 模型的用量（趋势图数据） | 最近 31 天 |

**为什么是投影单元而不是 Host RPC**：带 `wire` 块的单元天然客户端可见，于是顺着已有的读模型流动 —— 会话列表的投影列、`session.projections`、control 流、projection cache —— 不需要新服务、新 Remote 命名空间、新描述符。

**三个折叠共用一个事件推进步骤**（`advanceUsage`）。这是重点：`dsh-token-meter` 已经拥有 `tokenUsage`，"同一步内替换"与 `llm/retry-started` 边界只能有一处实现，否则三个单元会各自漂移、总和不再等于官方总额。host 自检用**逐行复刻官方算法**的 oracle 做差分断言：`sum(按模型) === sum(按天) === sum(按天×模型) === tokenUsage`。

拆成三个单元而不是一个，是为了给检查点体积一个明确上界：一年的每日总量（约 366 个小对象）与一个月的每日×模型明细（约 31 条），而不是 366×模型 条。

**天界**：按 Host 本机 UTC 偏移分桶（`utcOffsetMinutes` 可配，默认 `-getTimezoneOffset()`）。桌面端 Host 与用户同机，所以这就是用户时区；偏移随数据一起下发，浏览器用同一帧标注日期 —— 否则 UTC+8 用户清晨的用量会被标早一天。

> ⚠️ 这个偏移的**客户端半边曾经断链**：Host 一直有下发、wire schema 也强制校验，但客户端解析函数 `readDayUsage` 重建对象时把它吞了，于是聚合层读到 `undefined` 回落成 0，日期仍按 UTC 标注。**136 项自检全绿也没抓到**——因为 Host 与浏览器同机同时区时，偏移 0 与真实偏移渲染出**同一个日期**，错误互相抵消。现已修（透传 + 纳入行身份比较），并补了用**整天偏移**做的回归断言（整天不可能被时区抵消）；同样的断链还曾在会话视图的日期 chip 上复现过一次。

## 冷会话必须补读（一个真实 bug 的量化）

**面板要显示的每一个投影值都是"读的需求"，不能只看 `tokenUsage`。**

早期版本用「`tokenUsage` 缺失 ⇒ 需要读」来决定是否调用 `refreshProjections`。而**早于本插件写入的缓存行本来就有 `tokenUsage`**，于是那 9 个老会话的三个新单元永远没被算出来。在真实 profile 上量到的后果：

| | 值 |
| --- | --- |
| 全部会话 `tokenUsage` 合计 | 215,888,015 |
| 按模型 / 按天 合计（只有 1/10 个会话有新单元） | 185,685,524 = **86.0%** |
| 看不见的 | **30,202,491（14.0%）** |
| 热力图有色格子 / 环图扇区 | **1 天 / 1 个** |

同一个面板里表格显示 216M、图表显示 186M —— 两个总数不一致，而且"模型用量"只有一个模型，看起来就像模型商功能没做。

修复：队列改为按**面板显示的每一个值**判断（`tokenUsage` + 三个新单元），并加一次性探测 —— 没有 Host 半场的组合不会被拖去折叠所有日志。回归测试：过期行恰好各读一次、读完后图例和日历被填满、Host 缺单元时只探测一次就不再重试。零用量的会话也会产出合法的空单元（`routes: []` / `days: []`），所以探测完就不会反复重读。

**记账本身独立验证过**：解码全部 10 个真实日志（`session.v4.jsonl.zstd` 是**多帧 zstd**，例如 471 字节 = 3 帧、大会话 = 1440 帧；Node 的 `zstdDecompressSync` 只解第一帧，得按 magic `28 B5 2F FD` 逐帧切）重折官方算法 → **缓存 == 日志，10/10 一致，0 处不符**，且 **按模型 == 按天 == `tokenUsage`** 在真实数据上成立。

## 运行时一致性审计（面板自己发现口径不一致）

上面那个 14% 的 bug 是**用户肉眼**发现"表格 216M ≠ 图表 186M"才暴露的。自检只保**发版时**，面板**运行时**原本没有任何断言 —— 同类断链（折叠算错、漏桶、将来新增维度忘了同步）会再次静默少算。

`src/45-audit.js` 把这条件变成了机制：会话表读 `tokenUsage`，而模型环图/条读 `tokenUsageByRoute`，**两者必须相等**，于是面板自己检查

```
sum(tokenUsageByRoute.routes 四桶) === totalOf(tokenUsage)
```

不相等就在页脚亮一条带警告图标的提示，悬浮列出问题会话与两个数字。

**只断言这一条，是有意的范围收窄**：`tokenUsageByRoute` 是**全量保留**（无窗口）⇒ 必须精确相等；而 `tokenUsageByDay`（366 天）与 `ByRouteByDay`（31 天）是**窗口裁剪**的 ⇒ "小于总量"合法，断言相等会误报（现有测试基线里按天合计本身就大于总量，正是因为窗口语义）。所以自检里反过来把"按天合法超出总量**不得**报警"钉成回归。

审计只报"**值到齐了却对不上**"的行；缺单元的行走读取队列（见上一节），不重复报。它在**全量 rows** 上计算（与筛选无关 —— 筛选不该能把不一致藏起来），`useMemo([rows])` 保证实时 tick 不重算。

**验证**：`node scripts/dry-run-audit.mjs` 在真实 `$DSH_HOME` 上只读干跑 —— **55 个会话、0 漂移**（约 4.46 亿 token 逐行等式成立），所以它不会对现存数据误报。

## 模型名 / 网关名（没有"厂商"）

一条路由的标签**只有两个**，都来自权威来源 —— Host 的 LLM 注册表（设置里 Models 页面用的同一份数据）：

- `providerName` ← `ctx.llm.listProviders()` 的 `name`：`opencodegochat` → **`opencode go chat`**
- `modelName` ← `ctx.llm.listModels()` 的 `name`：`glm-5.3-flash` → **`GLM-5.3-Flash`**

渲染成 **`网关名 · 模型名`**，例如 `opencode go chat · deepseek-v4.1-flash`。

**刻意没有厂商（模型商）字段**：事件里只有 `provider/model`，而 `provider` 是**路由键**，在真实 profile 上同一个模型家族会以 `opencodegochat/*`、`opencodego/*`、`codexpert/*` 三种前缀出现 —— 它们是**网关**，不是模型公司。从模型 id 前缀猜一个公司名（`glm`→智谱、`mimo`→小米）看起来像事实，实际是猜测，而且猜不出来时只能显示网关名、反而更像错的。所以这个字段被整个删掉了：客户端产物和名称缓存里**不存在任何厂商名或厂商表**（自检静态断言）。

注册表读取失败或路由已卸载时回落到原始 id —— 历史比适配器活得久。

## 丝滑：不卡的做法

**问题**：`ApiSessionList.projectList()` 每次 manager 通知都无条件 `list.set({...})`，notifier 按帧批量 → **只要有会话在跑，列表快照的对象标识每帧都变（最高 60 次/秒）**。

**做法**（`src/40-data.js`）：投影闸门逐字段比较并**复用未变的 row 对象**（含 `tokenUsage` / `tokenUsageByRoute` / `tokenUsageByDay` / `tokenUsageByRouteByDay` 的数值与标签），数组只在真有变化时才换标识 → `useSyncExternalStore` 直接 bail out。刻意**不比较 `snapshot.ids`**：Host 每次发布都重建该数组，用它的标识判断恰好会让闸门在最需要它的那些 tick 上失效。显示字符串按 row 缓存在 `WeakMap`；`Intl.NumberFormat` 单例；排序 decorate-sort-undecorate；搜索 `query` 走紧急更新、过滤用 `useDeferredValue` 派生。

图表的跨会话聚合是本插件最贵的计算，因此**只在概览视图计算**（`useMemo` 里按 `filters.view` 短路），且只在 `rows` 标识变化时重算。hover 状态放在图表组件内部，移动指针不重渲染面板。

**实测保证**（自检模拟 Host 的 tick）：

| 场景 | 结果 |
| --- | --- |
| 3 行、30 次"标识变了数据没变"的 tick（**图表已挂载**） | **0 次重渲染** |
| 300 行、20 次同样的 tick | **仍然 0 次** |
| 真正改一个会话的用量 | 至多 2 次（消费新值 + 计数器落定） |

## 丝滑：动画与过渡

**统一原则：纯 CSS、默认常开，且"数据真变了才重放"。** 每个动画叶子把自己的数据摘要拼进 React `key`（`motionDigest()`）：数据变了就重挂载、重播动画；只重渲染而数据没变就不重放 —— 这正是 `data-animate` 从"用户操作后开 320ms"改成"常开作用域"之后仍然不抖的原因。

实现：根节点 `data-animate="true"` 是动效作用域，`MOTION`（`05-constants.js`）以 `--dsh-tup-fast/base/slow/stagger/ease/settle` 下发到根节点，时长、缓动、错峰一处改、全局生效。三层：

1. **图表生长**（本轮重点）：折线用 `pathLength="1"` 归一字长，CSS 用 `stroke-dasharray:1` + `dshTup-draw` 描出；环图整组 `dshTup-sweep` 旋转淡入（分段几何在属性上，CSS 不去抢）；热力图按**周列分组**错峰上浮（53 组动画，不是 371 个格子）；构成条 / 占比条 `scaleX` 从 0 长出来。
2. **组件与视图过渡**：面板进入、每个视图的各"带"依次错峰入场（`nth-child` 推延迟，最多 4 档）、表格行按页内序号波浪落位、tooltip 淡入、按钮 / 卡片 / 路由 chip / 图例的 hover 与按下反馈。
3. **计数**：KPI 的 rAF 计数仍只由用户操作开启（`COUNT_UP_MS = 320`）—— 它是唯一每帧写 state 的动画，`≤ 2 次重渲染`的闸门靠它守着。

`prefers-reduced-motion: reduce` 下全部关闭；折线在关闭时仍完整可见（`stroke-dashoffset` 归零）。

刻意**没有做**排序变化的 FLIP 重排动画：逐行 DOM 测量 + transform 记账的复杂度远高于收益。

## 图表为什么是手写的

平台内置种子表只有 React、React DOM、Cordis、client-store、ui-slots、ui-primitives、dockkit —— **没有图表库**；装一个要往 profile 里 pnpm 安装，并带来比整个插件还大的产物。所以折线、环图、热力图都是几百字节的 SVG 几何：

- 折线用"以相邻点为控制点、中点为终点"的二次贝塞尔平滑；y 轴取整到 1/2/5×10ⁿ；指针覆盖层按包围盒比例换算到绘图坐标。
- 环图用 `stroke-dasharray` / `stroke-dashoffset` 画弧，中心显示总量。
- 热力图是 53 周 × 7 天的 SVG 网格，五级强度，每格带 `<title>` 日期提示。
- 两张图都是 `role="img"` + `aria-label` 概述，并且**同样的数字都有文本形态**（表格、图例、KPI 条），不存在只活在图形里的信息。

| 功能 | 说明 |
| --- | --- |
| 视图切换 | 概览 / 会话（选择持久化；重置筛选不会把你弹回另一个视图） |

**schema 为什么是鸭子类型**：投影注册表对 `stateSchema` / `viewSchema` **只调用 `.parse(value)`**，抛错即视为"该行不可用"。所以本插件自带极小的 `{ parse }` 校验器，**零依赖** —— 用真正的 schema 库就得往 profile 装包，或 import 安装版解析不到的东西。

**为什么不走官方 tsdown / `clientBundle()`**：那套工具只存在于 DSH 源码仓库。安装版的 `resources/app.asar` 内没有 tsdown / esbuild / rollup / 任何构建包（实测搜索 0 命中），也没有 `clientBundle` 助手。`scripts/build.mjs` 用零依赖方式达到同样的产物契约。

## 自检

`node scripts/verify-host.mjs`（78 项）+ `node scripts/verify-bundle.mjs`（205 项），合计 **283 项**，退出码 0：

- **Host**：三个单元各自与官方 `tokenUsage` 算法的**差分等价**；按模型/按天/按天×模型归属；**跨午夜的同一步替换必须同时驱动三个单元**（按天分区的那一个若按 route 键做减法，会在旧的一天留下幻影并使 `sum(按天×模型)` 超出总量）；保留窗口裁剪边界（366 / 31 天，含"间隔大于窗口的稀疏历史也必须裁掉旧天"）；参照恒等性（drive 的 `Object.is` 闸门依赖它）；checkpoint JSON 往返与 wire schema；名称缓存的全部回落路径；畸形样本的有意分歧；三个键的注册。
- **浏览器**：产物新鲜度；**金额彻底不存在**（客户端与 Host 都断言）；入口/注册/布局与动效契约；KPI 四个数字；热力图格子数与着色数；折线序列数；环图段数与占比；网关名与模型显示名出现、且不存在任何厂商名；模型下钻与 chip 清除；**过期缓存行的补读**（`tokenUsage` 已在但新单元缺失时必须重读，且 Host 无此单元时只探测一次，`refresh` 会重新探测）；**运行时一致性审计**（按模型漂移被报且 tooltip 给出两个数字；按天合法超出总量**不报**；等待补读的行**不报**）；**Host 偏移真的被消费**（整天偏移必须让渲染日期正好移一天，且复原后回到原日期；**会话视图里的日期 chip 也必须用 Host 帧**）；**图表挂载下的渲染闸门**；视图切换与图表开关；排序/筛选（列恒显：列显隐菜单已按用户要求整体移除；目录 trigger 显示所选目录）；持久化与损坏回退；导出；**分页边界**（一页 20 行、无 spacer 行、页脚报页码与下一页、滚动不改行数、**跨页跳到当前会话**）；**动效契约**（作用域、生长关键帧 4 个、错峰 token、热力图列分组 53、归一字长）；**改名传播**（路由显示名变化无需 token 变化就能到趋势图例）；骨架屏与空态；失败读取的隔离与重试。

## 激活状态（需要重启一次）

Host 半场是**已加载模块**。DSH 的 HMR 默认不监听任何插件目录（`dsh-base` 的 `hmr` 行 `root: []`），而其"已接受模块"图是在**进程启动时**按监听根构建的 —— 运行中新增监听根不会追溯生效（已用临时激活标记实测确认 `apply` 未被重新执行）。

现在的状态（**以证据为准，不以这句话为准**）：

- **浏览器半场已生效**：侧边栏入口与新版面板（含图表）在线，`sidebar.panellist` 里的 `token-usage` 为 active。
- **三个投影单元在当前进程已生效**。验证方式：`$DSH_HOME/storages/session_projcache/sessions/<当前会话>.json` 里出现 `tokenUsageByRoute` / `tokenUsageByDay` / `tokenUsageByRouteByDay` 三个键，且 `tokenUsageByRoute.seq` 与会话事件数一致（检查点会序列化每一个已注册单元）。若这三个键**不存在** ⇒ 当前进程还没加载 Host 半场，需要重启 DSH。
- **老会话要补读**：早于本插件写入的缓存行里没有这三个键。修复后的读取队列会在**第一次打开面板**时补读它们（并发 3、预算 60，折叠日志但不激活 Agent，底部显示进度）。补读前概览会显示"还没有按天数据"并说明原因 —— 这是有意的优雅降级，不是崩溃。
- profile 的 `cordis.patch.yml` 里有一行 `hmr` 覆盖，把本插件目录加入监听根。**该行存在时启动的进程**，之后 `lib/*` 与 `src/*` 的改动都会热重载；删除该行即恢复出厂行为。

## 已知限制

- 统计是**日志口径**的累计用量，不是账单；金额功能已移除。
- **时间范围过滤的是"最近活动"**（创建时间与最后一次用户输入中较晚者），不是"最后一次记账时间"；冷会话的用量是检查点快照，写入有节流（默认 200 事件 / 5s 外加 `turn/end` 必写），可能滞后一个 turn。
- **标签只有网关名与模型名**：没有厂商字段，因为事件里只有 `provider/model` 而 provider 是路由键（网关）。同一个模型经不同网关访问会**分成两行**（例如 `opencodegochat/*` 与 `opencodego/*`），这是数据事实而不是合并失误。
- **天界取决于 Host 本机时区**（可配置）；跨午夜的会话按该日界切分。
- 按天数据只保留 **366 天**、按天×模型只保留 **31 天**；更早的数据在折叠时被裁剪，因此热力图是滚动的一年窗口。
- **归档会话也计入**：`sessionQuery.listSessions()` 是"完整逻辑语料"、`listPersisted` 无过滤，`ApiSessionList.list` 只丢弃 `cwd === undefined`（实测 10 个会话的 `cwd` 全在，0 个被丢弃）。`archivedSessionIds` 只被 archived-session-gate 用来阻止唤醒，不影响统计。跨工作区会话同样计入，列表也没有条数上限。
- 子代理会话是独立行，默认也计入总量。
- 热力图格子可点击 → 只看那一天的会话（筛选栏出现可清除的日期 chip）；**不可多选**，也没有按周/按月聚合。概览的日历、趋势与 KPI 刻意忽略日期筛选（否则图表会被自己刚点的那个格子塌成一天）；日期 chip 在会话视图里按 Host 帧标注，不回落 UTC。
- 虚拟化以固定行高为前提：行高恒为 54px，正是为了让每行等高；但分页（每页 20 行）之后窗口化永不触发，`windowRange` 只是保留代码。
- 折线图的 y 轴上限取整到便于阅读的刻度，因此曲线顶端不一定贴到网格线。
